# Week 01 Claude Code Prompt Pack

这个文件提供第一周每天可直接复制给 Claude Code 的提示词。
目标不是让 Claude 代写，而是帮助你理解代码、设计小练习、review 改动、做学习复盘。

---

## Day 1：整体理解项目

### Prompt 1：整体讲解
```text
请基于当前项目，用“先整体后局部”的方式告诉我：
1. 这个项目现在能做什么
2. 三个入口分别是什么
3. 哪个文件最值得先看
不要按文件顺序讲，请按一次请求的数据流来讲。
```

### Prompt 2：学习优先级
```text
如果我是一个 Python/算法背景、刚接触 TypeScript Agent 工程的人，
请基于当前项目告诉我：
1. 今天最值得先读的 3 个文件
2. 阅读顺序是什么
3. 每个文件我应该重点看什么
```

### Prompt 3：建立心智模型
```text
请不要展开太多细节，先帮我建立这个项目的最小心智模型：
- 入口是什么
- 核心逻辑在哪里
- tool 在哪里
- test 在哪里
- 哪些是“外层”，哪些是“内层”
```

## Day 2：理解 runAgent 主流程

### Prompt 1：解释 runAgent
```text
请解释 `src/lib/runAgent.ts`，但要满足：
1. 用 Python 工程师的视角解释
2. 先讲输入输出，再讲内部逻辑
3. 不要泛泛讲 TypeScript 语法，只解释我必须懂的部分
4. 顺便解释 `test/runAgent.test.ts` 是怎么约束这些行为的
```

### Prompt 2：按数据流讲解
```text
请按一次输入 `summarize "This is a long sentence"` 的真实流转过程，逐步讲解 `runAgent`：
- 先命中了什么判断
- 为什么会调用对应 tool
- 返回值是怎么拼出来的
```

### Prompt 3：只讲关键 TS 概念
```text
看 `src/lib/runAgent.ts` 时，我最应该掌握的 TypeScript 概念有哪些？
请只列最关键的 3-5 个，并结合这份文件解释，不要做语法百科。
```

## Day 3：理解 CLI 和 HTTP 入口

### Prompt 1：对比两个入口
```text
请帮我对比 `src/cli.ts` 和 `src/routes/chat.ts`：
1. 它们各自负责什么
2. 哪些逻辑应该放入口层，哪些应该放 `runAgent`
3. 用“分层设计”的角度解释，不要只讲代码表面行为
```

### Prompt 2：解释 route 层职责
```text
请解释为什么 `src/routes/chat.ts` 里要做 schema 校验，而 `runAgent` 不应该直接负责 request body 校验。
请用“系统分层”和“边界验证”的角度讲。
```

### Prompt 3：入口复用分析
```text
请说明这个项目是如何做到“CLI 和 HTTP 入口复用同一套 Agent 核心逻辑”的。
请指出关键文件和关键调用关系。
```

## Day 4：做第一个小改动

### Prompt 1：改动前分析
```text
我准备做一个很小的改动：[把这里替换成你的改动]。
请先告诉我：
1. 最可能需要改哪几个文件
2. 哪些测试会受影响
3. 我应该先读哪段代码
请不要直接给完整代码，只给我修改思路。
```

### Prompt 2：测试影响分析
```text
如果我把 fallback 回复格式从 `You said: ...` 改成别的文案，
请告诉我：
1. 哪些已有测试会失败
2. 为什么会失败
3. 我应该如何判断这是“正确失败”而不是写坏了代码
```

### Prompt 3：改完后的 review
```text
这是我做完的小改动，请帮我 review：
1. 有没有改多
2. 哪些地方有更简单的写法
3. 哪些地方会影响测试稳定性
请先讲问题和建议，不要直接重写。
```

## Day 5：自己补一个测试

### Prompt 1：只给方向不给答案
```text
我想自己补一个测试，但不想你直接写答案。
请你先给我：
1. 一个合适的测试目标
2. 这个测试应该放在哪个文件
3. 这个测试大概断言什么
不要直接给完整测试代码。
```

### Prompt 2：判断测试价值
```text
我准备加这个测试：[描述你的测试目标]。
请帮我判断：
1. 这个测试是不是在保护一个真实行为
2. 它和现有测试是否重复
3. 如果不够好，应该如何缩小到一个更清晰的行为
```

### Prompt 3：失败信息解读
```text
这是我新加测试后的失败输出：[粘贴失败信息]。
请不要直接给修复代码。
先告诉我：
1. 这个失败是不是符合预期
2. 它说明缺的是实现、还是测试写法有问题
3. 我下一步最小应该检查什么
```

## Day 6：加一个最小 toy tool

### Prompt 1：设计最小改动
```text
我想给这个 playground 加一个最小 toy tool：[wordCount / shoutText]。
请不要直接实现。
先告诉我：
1. 需要改哪些文件
2. 测试先写在哪
3. 这个改动为什么是“最小但完整”的练习
```

### Prompt 2：缩小复杂度
```text
如果我要加一个 `wordCount` tool，
请帮我把这个需求压缩到最小可学版本：
- 不要过度设计
- 不要引入新框架
- 只保留最值得练习的部分
```

### Prompt 3：完成后 review
```text
这是我加完 toy tool 后的改动，请帮我 review：
1. 分层是否还清晰
2. 测试是不是覆盖到了关键行为
3. 有没有为了“学习”而无意中写复杂了
```

## Day 7：学习复盘

### Prompt 1：周复盘
```text
这是我这周在 `agent-playground-ts` 里做的事情：[写你的总结]。
请帮我复盘：
1. 我真正掌握了什么
2. 我还薄弱的是什么
3. 如果下周只有 4 小时，最值得补哪两个点
4. 请按优先级给我下周学习顺序
```

### Prompt 2：基于代码暴露问题
```text
请根据我这一周改过的代码，判断我目前最薄弱的是：
- TypeScript 类型手感
- 分层设计手感
- 测试意识
- Agent 工程思维
请说明你的判断依据。
```

### Prompt 3：生成下周最小计划
```text
基于我这周完成的内容，请帮我生成一个“下周最小学习计划”：
- 总时长按 4 小时左右
- 只保留最高价值内容
- 不要把系统继续做大
```

---

## 使用原则

1. 优先让 Claude 做讲解、review、复盘
2. 不要一上来就让 Claude 直接给完整实现
3. 当你准备改代码时，先让 Claude 帮你缩小范围
4. 当测试失败时，先让 Claude 帮你解释失败，而不是直接修
